# API and Swagger Guide

## Open the interactive documentation

Start PostgreSQL and both applications using the root [README](../README.md).

| API | Swagger UI | OpenAPI JSON |
| --- | --- | --- |
| Catalogue | [http://localhost:8081/swagger-ui.html](http://localhost:8081/swagger-ui.html) | [http://localhost:8081/v3/api-docs](http://localhost:8081/v3/api-docs) |
| Orders | [http://localhost:8082/swagger-ui.html](http://localhost:8082/swagger-ui.html) | [http://localhost:8082/v3/api-docs](http://localhost:8082/v3/api-docs) |

Swagger UI displays the operations generated by springdoc from the controllers and DTOs. Expand an operation, select **Try it out**, enter the parameters or JSON body, then select **Execute**. Read the actual response code and body below the request. Swagger sends real requests and changes the real database.

There is currently no login or bearer-token configuration. The labels `1.0` and `1.2` come from `OpenApiConfig`; they do not require an `API-Version` header. OpenAPI specification version and application API version describe different things.

## Catalogue endpoints

All paths in this table use `http://localhost:8081`.

| Method | Path | Input | Success |
| --- | --- | --- | --- |
| POST | `/categories` | Category JSON | 201, CategoryDto |
| GET | `/categories` | None | 200, list of CategoryDto |
| GET | `/categories/{id}` | Category ID | 200, CategoryDto; 404 if absent |
| PUT | `/categories/{id}` | Category ID and Category JSON | 200, CategoryDto |
| DELETE | `/categories/{id}` | Empty category ID | 204, no body |
| POST | `/products` | Product JSON | 201, ProductDto |
| GET | `/products` | None | 200, list of ProductDto |
| GET | `/products/{id}` | Product ID | 200, ProductDto; 404 if absent |
| GET | `/products/by-category/{categoryId}` | Category ID | 200, list of ProductDto |
| PUT | `/products/{id}` | Product ID and Product JSON | 200, ProductDto |
| DELETE | `/products/{id}` | Product ID | 204, no body |
| POST | `/products/{id}/stock/decrease` | Product ID; query `quantity` | 204, no body |
| POST | `/products/{id}/stock/increase` | Product ID; query `quantity` | 204, no body |

Filtering products by an unknown category currently returns an empty list; it does not explicitly load and validate that category first. Category responses contain `productList`; product responses contain `categoryId`.

## Order endpoints

All paths in this table use `http://localhost:8082`.

| Method | Path | Input | Success |
| --- | --- | --- | --- |
| POST | `/clients` | Client JSON | 201, ClientDto |
| GET | `/clients` | None | 200, list of ClientDto |

| POST | `/orders` | CreateOrderDto JSON | 201, OrderDto |

| GET | `/orders/by-client/{clientId}` | Existing client ID | 200, list of OrderDto |
| PUT | `/orders/{id}` | Order ID; query `clientId` | 200, OrderDto |
| POST | `/orders/{id}/cancel` | Order ID | 200, OrderDto |
| DELETE | `/orders/{id}` | Cancelled order ID | 204, no body |
| POST | `/orders/{orderId}/lines` | Existing confirmed order ID; CreateOrderLineDto JSON | 201, OrderLineDto |
| GET | `/orders/{orderId}/lines` | Existing order ID | 200, list of OrderLineDto |
| GET | `/orders/{orderId}/lines/{lineId}` | Order and line IDs | 200, OrderLineDto; 404 if absent |

| DELETE | `/orders/{orderId}/lines/{lineId}` | Order and line IDs | 204, no body |

A line must belong to the order in the URL. The service has a `getAllOrderLines()` method, but there is no separate global controller endpoint exposing it.

## Complete manual scenario

### 1. Create a category

In catalogue Swagger, execute `POST /categories` with:

```json
{
  "name": "Computing",
  "description": "Computer equipment"
}
```

Expect 201 and copy the returned category `id`. Omit generated IDs in create requests. `productList` is a response field and is not used by the category service to create products.

### 2. Create a product

Execute `POST /products`. Replace `categoryId` below with the actual returned ID:

```json
{
  "name": "Keyboard",
  "description": "USB keyboard",
  "price": 29.99,
  "stock": 10,
  "categoryId": 1
}
```

Expect 201. Copy the returned product ID. Product name and description must be nonblank, price must be positive with at most two fractional digits and eight integer digits, stock must be nonnegative, and categoryId must identify an existing category.

### 3. Create a client

In order Swagger, execute `POST /clients`:

```json
{
  "name": "Alex Example",
  "email": "alex.example@example.com",
  "address": "Brussels"
}
```

Expect 201 and copy the returned client ID. Use a different email for another client; duplicate email detection is case-insensitive during creation. Although the current DTO lacks field constraints, provide complete valid data.

### 4. Create an order

Execute `POST /orders` using your real client and product IDs:

```json
{
  "clientId": 1,
  "lines": [
    { "productId": 1, "quantity": 2 }
  ]
}
```

Do not send `unitPrice`, `totalAmount`, `status`, `orderDate` or an order ID. The server obtains the price from the catalogue and calculates these order fields.

For the example above, the intended successful response is 201 with a confirmed order, unit price 29.99 and total 59.98. A representative response is:

```json
{
  "id": 1,
  "client": {
    "id": 1,
    "name": "Alex Example",
    "email": "alex.example@example.com",
    "address": "Brussels"
  },
  "orderDate": "2026-11-22T10:00:00",
  "status": "CONFIRMED",
  "totalAmount": 59.98,
  "orderLineList": [
    { "id": 1, "productId": 1, "quantity": 2, "unitPrice": 29.99 }
  ]
}
```

IDs and timestamps are illustrative, not guaranteed. Verify the actual result: the current persistence and compensation limitations are described in the [report](PROJECT_REPORT.md#current-limitations-and-next-work).

### 5. Verify the product stock

In catalogue Swagger, execute `GET /products/{id}`. Starting from stock 10 and ordering two units should leave stock 8, assuming no other stock requests occurred.

### 6. Change the quantity

In order Swagger, execute `PUT /orders/{orderId}/lines/{lineId}` with query parameter `quantity=3`. Send no JSON body. The intended result is stock 7 and order total 89.97. The unit price stays 29.99.

To add another line instead, use `POST /orders/{orderId}/lines` with:

```json
{ "productId": 1, "quantity": 1 }
```

The current implementation does not merge lines for the same product automatically.

### 7. Change the client

Create another client first. Execute `PUT /orders/{id}` and fill the `clientId` query parameter with that client's ID. This changes the client association, not the order lines or price.

### 8. Cancel and delete

Execute `POST /orders/{id}/cancel` with no body. Expect a cancelled order and restored stock for its lines. Then execute `DELETE /orders/{id}` and expect 204 with an empty response body. Deleting a confirmed order directly is rejected.

## HTTP codes and error payloads

| Code | Meaning in this application |
| --- | --- |
| 200 | Successful read, update or cancellation |
| 201 | Successful creation |
| 204 | Successful delete or stock adjustment; no response body |
| 400 | Invalid DTO, invalid quantity or invalid order operation |
| 404 | A requested resource was not found |
| 409 | Duplicate category/client, nonempty category deletion, insufficient stock or repeated cancellation |
| 503 | Catalogue connection failure or a catalogue server error translated by ProductClient |
| 500 | Unhandled failure; investigate logs rather than assuming the request was valid |

An exception translated by the advice produces this shape:

```json
{
  "status": 409,
  "message": "Example conflict message",
  "timestamp": "2026-11-22T10:00:00"
}
```

Some 404 responses deliberately have no body. Missing request parameters, malformed JSON and unhandled exceptions may use Spring's own error format. The current advice does not handle `OrderLineNotFoundException` explicitly, so missing lines on update/delete are a known gap. Swagger annotations document responses but do not themselves implement error handling.

## IntelliJ HTTP Client alternative

A `.http` file can contain requests such as:

```http
### Read products
GET http://localhost:8081/products

### Create an order with actual existing IDs
POST http://localhost:8082/orders
Content-Type: application/json

{
  "clientId": 1,
  "lines": [{ "productId": 1, "quantity": 2 }]
}

### Update a line quantity
PUT http://localhost:8082/orders/1/lines/1?quantity=3
```

These requests call the same controllers as Swagger. Swagger and IntelliJ HTTP Client are alternative manual clients, not separate application features.
